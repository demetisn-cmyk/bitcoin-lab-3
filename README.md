# Bitcoin Lab 4.0 · Research-first BTC/EUR lab

A research-first BTC/EUR forecasting dashboard. It is an educational experiment, **not investment advice or a trading system**.

## What it does
- Publishes a static dashboard suitable for GitHub Pages.
- Refreshes BTC/EUR daily prices using the public Kraken exchange API, with Binance and CoinGecko as fallbacks.
- Produces 30- and 90-day forecasts once per day and stores each forecast with its origin date, before its outcome is known.
- Evaluates prospective forecasts by horizon against a zero-return baseline; insufficient samples are shown as unavailable rather than zero performance.
- Runs a separate walk-forward Model Arena with zero-return, trailing historical-mean, shrunk-mean and 30-day momentum candidates. Historical simulations never enter the live forecast ledger.
- Reports MAE, RMSE, directional accuracy, skill versus zero baseline, sample counts and a non-overlapping-origin subset, separately for 30- and 90-day horizons.
- Keeps the forecast signal separate from the risk-adjusted research score.
- Offers CSV exports and records data freshness/source information.

## Scientific guardrails
- Forecasts are **prospective**: the ledger begins when the workflow first runs. It does not pretend that today's model generated historical forecasts.
- Do not tune parameters on the same observations used to report performance. Keep a final holdout period untouched.
- A positive score is not evidence of predictive skill. Compare out-of-sample forecasts with zero-return and simple historical-mean baselines.
- A missing API key, failed update, stale data, or empty history should be visible—not silently converted into a successful forecast.
- Crypto prices are volatile; historical relationships may fail. Nothing here recommends buying or selling Bitcoin.

## Deploy
1. In GitHub, open **Settings → Pages**.
2. Under **Build and deployment**, choose **Deploy from a branch**, select `main` and `/ (root)`, then Save.
3. This repository is public and the Pages workflow deploys the static site from `main`. Public source code must never contain secrets.
4. Open **Actions** and enable workflows if GitHub asks. The workflow runs on relevant code changes, on a daily schedule, and can be started manually.
5. Wait for the workflow to finish, then reload the Pages site.

## Optional CoinGecko key
Kraken is tried first and does not require an API key; Binance and then CoinGecko are fallbacks. If the CoinGecko fallback is needed, add a CoinGecko Demo API key under **Settings → Secrets and variables → Actions → New repository secret** with the name `COINGECKO_DEMO_API_KEY`. Never put the key in HTML, source files, screenshots, or commit history.

## Run locally
Requires Python 3.11+ and no third-party packages:
```bash
python scripts/update_lab.py
python -m unittest discover -s tests -v
```
The updater writes `data/latest.json` and `data/forecasts.json`.

## Model Arena methodology

`data/model_arena.json` is generated by `scripts/model_arena.py` from the latest price history. Each historical origin uses only prices available through that origin and requires an exact target date for the selected horizon. Metrics are calculated on a shared set of origins for each horizon. Daily-origin results overlap; the additional non-overlapping subset samples origins at horizon-sized intervals to reduce dependence, but it does not eliminate statistical uncertainty. The backtest is a historical simulation, not a record of forecasts actually issued at those dates, and it is never mixed into `data/forecasts.json`.

The live forecast ledger records model version and data cutoff on new entries. Existing entries are retained; maturity requires an observed close on the exact target date, so missing target dates remain pending instead of being silently shifted.

## Method summary
The baseline model uses a shrunk historical daily log-return mean over a trailing window. For horizon `h`, its expected log return is the trailing mean multiplied by `h` and a shrinkage factor. The risk-adjusted score subtracts a downside-tail proxy, a volatility uncertainty penalty and an assumed round-trip cost. These are transparent research knobs, not calibrated probabilities or validated trading edges.

The dashboard's interactive parameters are for **exploration only**; changing them does not rewrite forecasts already in the ledger. Forecast evaluation uses stored predictions and prices available after each forecast origin.

## Data and attribution
Market data is requested from Kraken's public API, with Binance and CoinGecko as fallbacks. Availability, granularity and rate limits can change. Data is denominated in EUR; it is not an exchange execution price.
